# Benchmarks

## GPU baseline

The current research baseline uses NVIDIA Ampere hardware.

A CUDA Redux optimization materially improved the experimental PearlHash GPU kernel relative to the earlier reduction implementation and produced real pool-accepted shares.

Important: experimental kernel throughput and production miner pool hashrate are not automatically interchangeable metrics.

## FK33 compute

FK33 V5.3 has demonstrated:
- functional PearlHash correctness
- resident job reload
- real-pool job handling
- coordinated multi-card operation

The project does not yet claim a pool-accepted PRL share generated by the FK33 V5.3 mining path.

## V7 runtime reliability

The same-generation renewal work fixed the long-job watchdog failure that previously caused card recovery after roughly 150 seconds.

Qualified behavior includes:
- valid same-generation renewals remain active past the old deadline
- wrong/stale renewals are rejected
- generation-change behavior remains valid
- loss of the independent safety supervisor still wins
- controlled coordinator loss still causes authenticated rollback

## PCIe build

Offline PCIe/XDMA V1:
- target: Gen3 x4
- routed
- timing clean
- DRC clean
- hardware resources instantiated
- hardware canary not yet executed

## Sidecar benchmark rules

Every result should report at least:

- GPU-only baseline
- GPU+FPGA end-to-end result
- transfer size
- transfer latency
- FPGA processing time
- synchronization overhead
- overlap strategy
- test duration
- correctness result

Do not report FPGA kernel speed alone as a sidecar speedup.

## FK33 break-even reference

The current local analysis and a reusable stdlib-only calculator are recorded
in [`run-logs/2026-11-15-pearlhash-fk33-breakeven.md`](run-logs/2026-11-15-pearlhash-fk33-breakeven.md)
and `tools/pearlhash_breakeven.py`. The matched offline RTX 3080 hurdle is
75.454830 Tera-MAC/s for the production-shaped full grid; a short live logged
rate is reported separately because its timing scope differs. The report
does not claim an FK33 speedup. A GPU benchmark was not started while a GPU
workload was active.

The calculator accepts measured FPGA cycle counts and transfer parameters;
for example:

```sh
python3 -I -S tools/pearlhash_breakeven.py \
  --gpu-tmacs 75.454830 \
  --fpga-clock-mhz 250 \
  --fpga-count 1 \
  --pcie-bytes 1073741824 \
  --pcie-effective-gbps 3.15 \
  --measured-cycles 150000000 \
  --cycle-evidence ESTIMATE
```

Use `--cycle-evidence MEASURED` only for cycles collected from an actual
measurement; use `ESTIMATE` for planning values. GPU rates can be labeled
`RETAINED_OFFLINE_MEASUREMENT`, `RETAINED_LIVE_LOG`, `ESTIMATE`, or
`USER_INPUT`; unrecognized rates default to `USER_INPUT`. CPU timing JSON also
requires `--cpu-stage-evidence MEASURED` or `ESTIMATE`. This calculates only
from supplied values; it does not launch a benchmark or touch CUDA/PCIe/FPGA
APIs.
