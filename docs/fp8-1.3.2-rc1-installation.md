# FP8 candidate setup and installation guide — 1.3.2-rc1

**Inactive experimental candidate; not approved for live mining or external redistribution.** This guide concerns the deploy7-derived setup-tools candidate, not a production installer.

## Current behavior

The setup wizard creates a local `PREPARED_INACTIVE` profile. It stores pool endpoint and wallet/public identifier fields, but the profile is not consumed by the deploy7 worker. It does not configure a functional pool job protocol, start a miner, install a service, contact a pool, submit shares, enable fees, or change payout routing.

## Local preparation

Use a private directory in a trusted local terminal. Do not include real credentials in examples, issues, logs, or support requests.

```sh
umask 077
mkdir -p "$HOME/.config/sidecar-prepared"
chmod 700 "$HOME/.config/sidecar-prepared"
python3 tools/setup_wizard.py --out "$HOME/.config/sidecar-prepared/profile.json"
chmod 600 "$HOME/.config/sidecar-prepared/profile.json"
```

The wallet prompt is hidden, and the wizard refuses to overwrite an existing destination. Pool URLs containing userinfo, query, or fragment data are refused. The resulting file is sensitive and should remain local. Device selection only records a preference; it does not launch CUDA.

## Host requirements

Retained Linux x86-64 binaries need `libcudart.so.12` even in CPU fallback, plus `libstdc++.so.6`, `libgcc_s.so.1`, `libm.so.6`, `libc.so.6` and the ELF loader. CUDA/NVIDIA libraries are not bundled. Observed GLIBC 2.38 / GLIBCXX 3.4.29 symbol versions are not a validated distro matrix. Minimum application driver, Python, and VRAM requirements remain unresolved. `tools/dependency_preflight.py --mode cpu-offline` reports local dependency visibility without installing anything.

The existing stage operation is validation-only unless explicit `--apply` is passed; any later apply exercise must use a disposable per-user root, not a miner configuration directory. No services are installed or enabled by this candidate.
