# FP8 candidate license and dependency status — 1.3.2-rc1

**External redistribution is not cleared.** The current result is an evidence/rights gap, not a finding that a particular license is incompatible.

The retained deploy7 inventory covers seven Cargo lockfiles and 366 registry crate versions. Twenty-five versions lack cached source/license evidence in that audit environment; the three core locks contain 24 such versions. Eight path crates lack standalone license declarations. Some may be optional or platform-specific; their absence from cached metadata does not show that they are shipped in the Linux runtime or legally incompatible.

Notices present include Pearl ISC, Plonky2 MIT/Apache-2.0, component ISC/MIT, XMSS CC0, and Bitcoin Core attribution material. A target-specific file/binary-to-license mapping is incomplete. Written redistribution rights for Sidecar/GPU-A/GPU-B prebuilt executables are not established. CUDA/driver libraries are not bundled; future bundling requires a separate terms review.

A **separate, not-integrated GPU-A Stratum gateway** pins direct Python requirements to aiohttp 3.13.5, bitcoin-utils 0.8.2, fastjsonschema 2.21.2, loguru 0.7.3, pydantic 2.13.4, and pydantic-settings 2.14.2. The package registries report Apache-2 (aiohttp also declares upstream notice material), MIT (bitcoin-utils, loguru, pydantic, pydantic-settings), and BSD (fastjsonschema), respectively. These are not deploy7 dependencies and do not clear the deploy7 or GPU-A binaries. The gateway's full resolved transitive/native SBOM and notices remain unverified.

Before external release: recover exact locked sources/checksums, generate a target-specific SBOM, map local crates and notices, obtain publisher/owner rights for the prebuilt artifacts, and record reviewer clearance. Read the package-local audit for full evidence.
