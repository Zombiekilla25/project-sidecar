## Defects still open and new regression

An end-to-end endpoint test built a fresh signed descriptor, release
authorization, handoff, and runtime manifest, then ran the actual
`execute_request` route with only `_NativeLibFtdi` replaced by the candidate's
fake backend. The operation opened and closed the fake backend once, consumed
the authorization, and ran both fixed scans. Transport reconstructed its
permit with a new random nonce; endpoint then validated the result against its
original permit. The mismatch caused:

```text
endpoint status: REFUSED
phase/code: LOCAL_VALIDATION / LOCAL_VALIDATION_FAILED
authorization consumed: yes
fake open/close: 1 / 1
```

This is a reproducible endpoint integration defect. It does not indicate a
hardware access; the backend was a test fake. The report and reproduction are
stored in `tests/reference/fk0957_endpoint_permit_reconstruction_attack.py`.

Receipt and supervisor findings remain open because the receipt implementation
was not changed in this commit. The independent cleanup attacks still show:

- same-UID caller can write a terminal receipt and caller-controlled
  `launch_closed` can produce a restorable `CONFIRMED_EXITED_SUCCESS`;
- receipt destination, terminal state, and parent-directory replacement races
  are not detected;
- PID reuse and inaccessible `/proc` are refused, and SSH rc 255 remains
  non-restorable `TRANSPORT_FAILED`.

The campaign also continues to reproduce startup injection before bootstrap
validation, direct bootstrap trust-marker acceptance, absent pinned release
issuer provisioning, bridge handoff claims for wrong bridge/client/lane being
accepted when signed, incomplete runtime source hashing, missing exclusive
bridge ownership gate, and documentation claiming null transport hashes while
the native adapter exists. These leave startup, release/handoff authority,
provenance, and launch/documentation acceptance open.
