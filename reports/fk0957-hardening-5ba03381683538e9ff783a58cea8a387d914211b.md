## Permit identity trace

The release authorization nonce now propagates from signed request context to
the endpoint permit, and transport verifies descriptor digest plus nonce
before native transport. Mutation of the nonce at either endpoint/transport
binding refuses before backend construction.

However, transport reissues a permit object with the same nonce and a new
private one-use token. I independently simulated supervisor authorization
consumption, then ran the exact endpoint route against the candidate fake
backend. Result:

- authorization was consumed before child execution;
- endpoint and observation nonce matched;
- endpoint permit remained active but was not consumed;
- a second permit token with the same nonce was consumed;
- fake backend opened and closed once, and the fixed operation completed;
- endpoint refused at `LOCAL_VALIDATION / LOCAL_VALIDATION_FAILED`.

Therefore nonce value binding is present, but permit identity/token continuity
is not. Without supervisor capability, the request refuses before consuming
authorization and before fake backend open.

The reproducible independent probe is
`tests/reference/fk0957_endpoint_permit_reconstruction_attack.py`.

## Legacy receipt quarantine

The commit range since 387 quarantines the legacy same-UID receipt protocol:
terminal transitions are refused by its writer, the status schema is v2 with
no `launch_closed` field/parameter, terminal receipt states validate as
`UNKNOWN`, and `restore_allowed()` always returns false. Production source has
no imports of this legacy receipt module outside its tests; the topology RGB
orchestrator uses the protected supervisor client.

Independent attacks directly replaced receipt bytes with a forged
`EXITED_SUCCESS` for a missing PID, submitted stale status, replayed a status
under a different operation ID, and attempted the old `launch_closed`
argument. The forged, stale, and replayed records produced `UNKNOWN`; the
legacy argument and terminal transition were rejected; none could authorize
restore. The focused result is in
`tests/reference/fk0957_legacy_receipt_quarantine_attack.py`.

`LEGACY_RECEIPT_AUTHORITY_PASS=YES` for cleanup/restore/evidence authority.
The underlying same-UID receipt file remains writable by its owner, but its
records no longer authorize a sensitive action in the reviewed production
route.
