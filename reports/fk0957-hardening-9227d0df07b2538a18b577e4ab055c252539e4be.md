# FK0957 independent hardening audit: `9227d0df07b2538a18b577e4ab055c252539e4be`

Audited in the watcher-created detached worktree. This SHA adds a receipt/status
protocol contract and tests. The protocol validator is not wired into the
remote endpoint or RGB orchestrator: the handoff explicitly says the remote
receipt writer/status query is still absent and cleanup after SSH loss remains
unknown.

## Checks

- Watcher suites passed: corrected oracle (28 valid, 249,572 invalid, zero
  mismatches; 1,015 additional cases and 52 model tests), acceptance, campaign,
  native runtime, and diff check.
- Focused candidate suite passed 31 tests across cleanup protocol, RGB
  orchestrator, and remote endpoint.
- Independent endpoint fixture now binds the manifest to all 12 declared
  release source files. Baseline signed fixture validates, transport executes
  once, replay is rejected, all 12 source tamper cases reject, wrong production
  HEAD rejects, and the default unprovisioned issuer config refuses before
  transport. The handoff fixture still accepts changed bridge hash, client and
  lane values when signed by the test issuer; there is no local expected-value
  pin or live ownership observation.
- The inherited SSH 255 fix is correct: a canonical refusal with rc 2 is
  `REMOTE_PROCESS_CONFIRMED_EXITED`; rc 255 with the same bytes is
  `REMOTE_STATE_UNKNOWN`. Stderr remains hidden. The cleanup status protocol is
  not yet invoked by the production flow.
- Direct startup attacks still execute harmless sentinels before bootstrap
  validation. The forged launcher marker still passes bootstrap self-test.
- Direct transport attacks still reproduce: fabricated unregistered permit
  passed twice through `_run_consumed_permit()` and fake-opened twice; direct
  `_authorize_remote_permit()` accepted four invented digests for a valid
  descriptor permit, after which the public transport function fake-opened
  once. Both bypass the endpoint's signed release authorization. The same
  internal route accepts a wrong clean HEAD under the injected test Git state.
- Direct `_sign_validated_remote_record()` still signed the minimal fabricated
  record with a disposable test key; signature verified and no evidence file
  was written. Startup and direct signing/transport remain reachable through
  importable Python modules.
- Additional deterministic malformed-input sweep covered 231 receipt field
  type combinations, 165 top-level status combinations, and 231 nested receipt
  combinations. `validate_status()` returned UNKNOWN safely. Direct calls to
  `validate_receipt()` leaked `TypeError` for list/dict `state`; utility calls
  `restore_allowed([])` and `receipt_transition_allowed()` with unhashable
  values also leaked `TypeError`. These helpers currently have no production
  caller in the candidate path, but their public malformed-input behavior is
  not total. An additional seeded campaign (`0x09572026`) generated 50,000
  malformed/replay/stale combinations; all returned UNKNOWN and none became
  restorable.
- `docs/phk2-fk0957-topology-discovery-offline.md` still claims the transport
  source hash is null until a production adapter exists, although the adapter
  and hash function are present. The remote split document correctly says
  issuer pins and cleanup integration are still missing.
