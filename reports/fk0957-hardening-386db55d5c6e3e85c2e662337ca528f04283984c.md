## New independent defects

### 1. Direct internal route skips descriptor signature validation

The internal helper validates the signed release request, handoff, and runtime manifest, but only compares `permit.descriptor_evidence_sha256` with the request descriptor digest. It does not call the pinned descriptor evidence verifier or the normal permit issuer. Both `_ACTIVE` and `_REMOTE_AUTHORIZED_PERMITS` are ordinary mutable module dictionaries reachable through direct Python imports.

I used temporary Ed25519 release/handoff keys to make a valid request whose descriptor bytes were deliberately not signed descriptor evidence. I forged the exact expected FK0957 `DiscoveryPermit` record in `_ACTIVE` and placed the signed request bytes in `_REMOTE_AUTHORIZED_PERMITS`. The public `run_fk0957_topology_discovery()` returned an observation and the fake backend opened once. The runtime manifest and request signatures were verified by production code; only descriptor evidence signature verification was absent from this direct route. The actual native backend was never used.

This leaves an importable internal route that can bypass the trusted descriptor signer check after a valid signed release request is available. It also shows why process-local mutable permit registries do not themselves provide an authority boundary.

### 2. Caller-controlled source prehash permits transport before mismatch refusal

`_run_consumed_permit()` still accepts `source_sha256_before` as a caller argument. With a valid temporary signed request and a runtime manifest that passed the real source/native hash validation, I supplied an all-zero source hash. The fake backend opened, completed the fixed scans, and closed; only then did the post-operation comparison refuse on source hash mismatch. This does not permit signing, but it violates fail-before-open behavior for a source-hash mismatch and gives direct callers control over the pre-operation hash value.

The exact reproduction is saved in `tests/reference/fk0957_transport_internal_authority_attacks.py`.
