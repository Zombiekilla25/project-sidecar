## Permit continuity

The change binds the permit nonce to the signed release authorization, but
does not preserve the permit's single-use token. In the supervisor-authorized
fake-backend path:

1. endpoint issues permit P0 using the signed authorization nonce;
2. supervisor has already consumed the authorization before child launch;
3. transport revalidates the request and reconstructs permit P1 with the same
   nonce but a new private token;
4. P1 is consumed, transport opens/closes the fake backend and completes the
   two fixed scans;
5. endpoint validates the result against P0, which is still active but not
   consumed, and refuses at `LOCAL_VALIDATION / LOCAL_VALIDATION_FAILED`.

The independent probe observed matching P0/result nonces, P0 active and not
consumed, and one other matching-nonce permit consumed. Authorization was
consumed, fake open/close was 1/1. No physical backend was used.

Without a simulated supervisor capability, authorization is not consumed and
the route refuses before transport. The protected route therefore blocks
direct callers, but the real authorized endpoint route still cannot complete.

`--apply` is deliberately unimplemented. The supervisor deployment and
trusted authority are not established, so the unsafe legacy helper cannot be
ignored as a closed system boundary.
